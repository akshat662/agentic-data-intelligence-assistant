# Agentic Data Intelligence Assistant (ADIA)

## Project Overview

ADIA is a LangGraph-based agentic data analysis system. An LLM plans and
orchestrates an analytical workflow, but every computation — statistics,
aggregation, ML fitting, SQL execution — is performed by deterministic
Python/SQL tools, not by the LLM itself. The LLM's role is restricted to
reasoning about *what to do next*; it never produces analytical results
directly.

This repository currently contains only the **project foundation**
(structure, tooling, configuration). No analytical, orchestration, or
LLM-calling code exists yet — see [Implemented Features](#implemented-features)
below.

## Problem Statement

"Chat with your data" tools built directly on top of an LLM ask the model to
read raw data (or a sample of it) and produce numeric answers, summaries, or
charts in the same generative pass as its natural-language response. This
conflates two fundamentally different tasks: *deciding what analysis to run*
and *actually running it*.

## Why Existing LLM-Based Data Analysis Can Hallucinate

When an LLM computes an answer directly — e.g. "the average order value is
$42.17" — that number is a token-by-token generation, not the output of an
arithmetic operation. Even with the data in context, LLMs:

- Miscount rows, misread columns, or silently drop outliers/NaNs.
- Cannot guarantee reproducibility — the same question can yield different
  numbers on different runs.
- Provide no verifiable trail from a reported number back to the rows and
  operations that produced it.
- Degrade further as table size grows beyond what fits usefully in context.

The result is answers that *look* authoritative but carry no computational
guarantee of correctness.

## Project Objective

Build a system where:

- An LLM plans a multi-step analytical workflow (a graph of steps) based on
  a user's question and the available data schema.
- Every actual computation is delegated to deterministic, testable tools
  (pandas/DuckDB/statistics/ML libraries).
- Every result carries **evidence/provenance** — a record of which tool,
  which query, and which rows produced it.
- A **validation layer** checks tool outputs and plan consistency before a
  result is surfaced to the user.

## Why This Is Not Just an LLM Wrapper

A "chat with CSV" wrapper sends data (or a description of it) to an LLM and
returns whatever text comes back. ADIA is architected so the LLM never
touches raw data values for computation:

- **Separation of planning and execution** — the LLM emits a plan/tool call;
  a deterministic tool executes it; the result is fed back structurally, not
  regenerated by the model.
- **SQL/pandas as the source of truth** — numeric results come from DuckDB
  queries or pandas/ML operations, which are unit-testable independent of
  any LLM.
- **Evidence tracking** — every reported figure is traceable to the
  operation that produced it, enabling audit and reproducibility.
- **Validation layer** — outputs are checked against expected shapes/types
  before being trusted, rather than accepted as-is from the model.

In short: the LLM decides *what* to compute; it never *is* the computation.

## Future Roadmap

1. **Foundation** *(this milestone)* — repository structure, dependency
   management, linting/testing configuration, documentation scaffolding.
2. **Contracts** — pydantic models for plans, tool calls, tool results,
   evidence records, and validation outcomes (`adia/models`).
3. **Data layer** — DuckDB-backed data access and schema introspection
   (`adia/data`).
4. **Deterministic tools** — statistical, SQL, and ML analysis tools with
   unit tests (`adia/tools`).
5. **Validation layer** — checks on tool output correctness and plan
   consistency (`adia/validate`).
6. **Evidence/provenance tracking** — linking every reported result back to
   the operation that produced it (`adia/evidence`).
7. **LangGraph orchestration** — graph-based planning and execution flow
   (`adia/graph`, `adia/agents`).
8. **API layer** — FastAPI service exposing the assistant (`adia/api`).
9. **UI layer** — Streamlit front end (`adia/ui`).
10. **Benchmarking** — analytical accuracy/regression benchmarks (`bench`).
11. **Deployment** — Docker packaging.
